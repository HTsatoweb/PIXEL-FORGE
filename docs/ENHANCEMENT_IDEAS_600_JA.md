# PIXEL FORGE STUDIO v54.0 強化案 600項目

> v54.0のZIP内にあるREADME・変更履歴・検査結果・HTML/JavaScript構成を確認して作成した提案一覧です。
> 既存機能と重複するものは「新設」ではなく、精度・操作性・安全性・管理性を高める改良として整理しています。
> 実装前には該当機能の現行挙動を再確認し、既存の作品形式（.pforge version 5）、IndexedDB schema version 3、既存ID/イベント経路を壊さない設計にします。

## 実装可能性の前提

- 現行のブラウザ型HTML/CSS/JavaScript、Canvas 2D、IndexedDB、Web Worker、Service Workerを基本に実装する想定です。
- ネイティブアプリ化、サーバー必須機能、外部AI API、完全なPhotoshop互換など、現行の構成だけでは保証できないものは案に含めていません。
- 筆圧・傾き・GIF/動画などはブラウザーや端末の対応状況に応じたフォールバックを用意する前提です。
- 600項目は600個の巨大な独立エンジンという意味ではなく、小・中規模の改良を分割した実装単位です。

## 優先度の目安

- **先に実装**：保存保護、入力安定性、Undo/Redo、モバイル操作、速度・診断。
- **次に実装**：ブラシ品質、レイヤー、選択、色、図形・テキスト、書き出し。
- **段階的に実装**：高度な画材シミュレーション、マスク、調整、アニメーション補助。

## 実装時に守るべきこと

1. 既存機能を削除せず、先に現行挙動のテストを作ってから追加する。
2. .pforgeの形式version 5とIndexedDB schema version 3は、必要性を検証せず変更しない。データ構造を変える場合は後方互換の移行処理を用意する。
3. スマホ・PCの両方で操作確認し、描画中にパネル開閉や画面回転が起きてもストロークが壊れないようにする。
4. 重い処理はWorker化・分割処理・進捗表示・キャンセル・失敗時復旧をセットで実装する。
5. PSD等は「対応できる範囲」を明記し、未対応機能を完全互換と表現しない。
6. リリースごとに構文検査、参照検査、保存/読込、Undo/Redo、レイアウト、実機入力のテスト結果を記録する。

# PIXEL FORGE STUDIO v29.0 — 検査結果

## ブラウザ相当操作テスト

Chromiumのモバイル相当画面とタッチイベント相当の自動テスト、および保存失敗・作品読み込み時の復旧テストを実施しました。

Chromiumでスマホ／タブレット相当のビューポートを設定し、HTML・CSS・JavaScriptを読み込ませて操作しました。

| 画面サイズ | 新規作成 | 設定開閉 | 背景タップで閉じる | 保存 | ホーム移動 | 横はみ出し |
|---|---:|---:|---:|---:|---:|---:|
| 390×844 | OK | OK | OK | OK | OK | なし |
| 320×700 | OK | OK | OK | OK | OK | なし |
| 844×390 | OK | OK | OK | OK | OK | なし |
| 768×1024 | OK | OK | OK | OK | OK | なし |

確認内容：

- ホームの「新しい作品」から新規キャンバスを開き、480×360の編集画面へ遷移。
- スマホドックの16個のボタンと横スクロール幅を確認。幅320pxでページ全体に横スクロールが発生せず、ドック最終ボタンまで到達。
- タッチイベント相当で消しゴムツールを選択し、設定ボタンを開閉。
- 設定ドロワーの幅、スクロール量、背景スクラブのクリックで閉じる動作を確認。
- 横向き844×390ではドックを隠したまま上部バーの設定ボタンを再表示し、パネルが使えることを確認。
- 保存操作から `.pforge` ダウンロードが発生し、進捗バーが100%に到達。
- ホーム移動時も `.pforge` バックアップのダウンロードを確認し、ホーム画面へ戻る。
- 保存進捗終了後にオーバーレイが閉じることを確認。
- 未捕捉のJavaScript `pageerror` は0件。
- タッチ相当テストで消しゴムのタッチ入力、タップモーション、ドック横スクロール、設定パネルのタッチ開閉、背景タッチによる閉じ動作を確認。
- IndexedDB拒否時の未保存作品読み込みでは、読み込み前に `.pforge` を書き出してから読み込み作品を編集画面に表示。
- バックアップ書き出し自体を強制失敗させたテストでは、ホーム移動がキャンセルされ、編集画面に作品が残ることを確認。

## 保存テストの重要な制限

操作テストは隔離された `about:blank` 相当のページで実施したため、ChromiumがIndexedDBアクセスを拒否しました。その結果、このテストで確認できたのは **IndexedDB失敗時の `.pforge` フォールバック** です。実際の `http://localhost` やHTTPSオリジンでIndexedDBへの保存・読み戻しが成功することを、この環境では確認できていません。コンソールにはテスト環境によるIndexedDB `SecurityError` が出ますが、保存コードはバックアップ経路へ切り替わり、ダウンロードが発生しました。

## 実機で残る確認

- iPhone Safari／Android Chrome上の実タッチ入力、実際の画面回転、ソフトキーボード、ノッチ／ホームインジケータ。
- 実機のIndexedDB保存、容量不足、複数レイヤー大容量作品での保存と再読み込み。
- iOS／Androidのファイルダウンロードマネージャーでの `.pforge` 保存と再読み込み。
- インストール済みPWAのService Worker更新。
- PC実機でのPSD、筆圧、ショートカット、ドラッグ描画の回帰確認。

実機確認を行う場合は `run_local_server.bat` でローカルサーバーを起動し、PCとスマホを同じWi-Fiに接続してください。重要な作品はブラウザ内ライブラリと `.pforge` ファイルの両方に保管してください。
